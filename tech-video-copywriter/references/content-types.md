# 内容类型与调用目录

## 账号定位

从全球前沿科技事件、现场体验和产品实践中，选择值得大众关注的变化，讲清新能力、背后原因以及对人的影响。账号是中国科技自媒体，主平台为视频号；每条内容重新识别核心共鸣人群，不固定年龄或职业。产品商单属于用户明确纳入的业务范围，合作任务单独识别。

## 如何选择

预设 11 个创作入口：T01–T07 按主要观看问题划分，T08–T11 按用户常用制作任务划分。它们使用同一个目录，但不假装彼此完全互斥。

每篇成稿确定一个主类型，另加至多两个有用的辅助标签，不为每个标签复制一份案例或规则。题材标签可以是 AI、机器人、汽车、基础科学；形式标签可以是榜单、合集、对比、回顾。情绪和语言风格不作为主类型。

主类型判定顺序：

1. 明确以履行品牌合作目标为任务：T10 产品商单；附测评、vlog 或发布会标签时，同时满足相关证据要求。涉及测试仍须读取 T09，涉及亲历仍须读取 T08。
2. 非商单，核心承诺是亲自验证产品表现：T09 产品测评。
3. 用户指定线下大会 vlog，或核心观看价值来自在场观察、亲历发现与现场解释：T08 线下大会 vlog。它可以围绕观点或能力组织，不必讲完整行程；现场只是素材来源且用户未指定 vlog、主要任务是整理公告时归 T11。
4. 核心任务是解释一场发布中最重要的更新：T11 发布会。
5. 其余按核心问题选 T01–T07。用户已指定内容学习类型时按指定主类型归档，可加必要辅助标签；使用某条跨类型方法不自动改变主类型。仅仅在大会发布的产品不自动归 T11；产品演示不自动归测评；有会场画面不自动归 vlog。

同一新闻的三个传播方向允许选择不同类型，确定方向后再确定本篇主类型。榜单／合集按其主要观看收益归类：创新产品合集可归 T01，科研进展合集可归 T02，趋势证据合集可归 T06。无法找到共同观看收益时先收敛选题。榜单保留清晰排序逻辑和递增感，每项只突出最有价值的问题、突破、画面或意义，避免项目之间完全同构。

## 常用容量与持续学习

各类型常用案例上限、当前数量与归档规则统一见 [case-gaps.md](case-gaps.md)。用户说“内容学习”即按 `case-update.md` 自动录入、分析与归纳；满额只影响默认调用哪些案例，不阻止新稿学习。测评和商单暂缓主动征集，但主动提供的材料照常处理。

## T01 新品与新能力

- 观看问题：它具体做成了什么，相比过去新增了什么能力，这会怎样改变一个任务或使用方式？
- 素材：完成结果、动作或任务、前后对比、使用门槛、必要参数、系统分工。
- 类型方法：先读 [新品内容路线](type-methods.md#product-routes)。可选择生活场景价值（C02 服务任务、C22 连续体验、C27 产品分层与长期接受）、能力变化到工作方式变化（C18、C23）、系统分工到完整工作流（C19；C23 补充任务先行与运行条件）；P02 补充动作结果先行、按控制对象与受益范围扩展能力的条件性组织；具备强演示与明确对手时保留 [产品战绩](type-methods.md#product-record)。
- 证据顺序：优先选择观众最容易理解的入口；任务结果、价格场景或指标对比均可按条件承担入口，不固定所有稿都先跑分或先动作。指标要解释考什么、比较什么，再与任务变化连接。
- 新材料方法：C96 修改成本、C99 成品交接、C100 载体路径、C102 资产起步、C104 服务入口；C91 可交互状态与 C95 阶段任务；C77 时间窗口合集、C78 结构观察、C79 开放产物、C81 连续热点、C85 算力获得；C68 补充作业反馈与恢复，C71 补充形态到限制；C57 补充机器人任务与复制条件，C58 补充用法先行回溯能力，C65 补充同对象业务理解到选择；C48 补充开放采用，C54 补充理解、记忆与执行的工作关系；C37 用状态与区域对照解释光学控制，C38 用动作难度解释控制层级，C39 补充成本到采用条件，C44 补充 [创新合集](type-methods.md#product-collection)。常用状态见索引，归档不撤销方法。
- 判断尺度：生活价值已经兑现时可停在使用场景；系统变化有足够材料时可展开到工作方式或产业关系。不要把小产品强行写成文明事件，也不要因担心拔高而删除有具体机制支撑的意义。
- 常见失败：参数表替代能力解释；组件无分工关系；后果越来越多而主问题不再推进；官方演示被写成亲测。
- 边界：亲自验证表现与适用性为主转 T09，多项发布的整场判断为主转 T11。用户指定本类的模型更新可以借用 T06 角色跃迁方法，不自动重分类；原有方法的适用条件仍需满足。

C106 将代际变化接到工作任务，C109 从观赛效果回溯制作与分发；均合并到 [能力与用途路线](type-methods.md#product-routes)。

C122 与 C125 是哼唱、采样的独立新输入，强化自然表达起点；C124 补充开放范围到使用选择；C123 强化时间窗口合集。分别合并到 [能力与用途](type-methods.md#product-routes) 及 [创新合集](type-methods.md#product-collection)。

C131 参数到便携约束、C132 效果到交付、C133 用户入口到选择、C135 官方产物到比较职责，合并至 [能力与用途路线](type-methods.md#product-routes)，原稿保持各自身份。

## T02 科学与技术突破

- 观看问题：原先难在哪里，今天究竟推进了哪一步？
- 素材：旧瓶颈、具体成果、关键机制、比较尺度与验证状态。
- 推进：可理解的成果 → 旧难题 → 突破机制 → 能力边界 → 实际意义。
- 类型方法：读取 [科研结果、机制与作用范围](type-methods.md#science-routes)，按材料选择使用阻力到流程增益（C31）、结果与机制对照（C34）、混合系统反馈（C35）、身体信号与自主动作连接（C64）；C66、C72 在流程增益中补充时间对照与服务可及，C86 补充群体实验到设计启发，C94 补充短动作稿；不把各篇规定为同一模板。
- 可选方法：AI 科研成果读取 [科研瓶颈迁移](type-methods.md#science-bottleneck)；类比负责解释技术关系，随后回到机制，不让比喻吞掉解释。科研合集先找到统一问题。
- 常见失败：只宣布历史性；用陌生指标充当高潮；从单次成果跳到所有难题已经解决。
- 边界：解释突破本身归本类；主要证明跨事件的未来变化归 T06。

C145 补充大会信息收窄为商业训练任务：难点 → 熟悉对照 → 机制响应 → 应用扩展，合并至 [科研任务与机制](type-methods.md#science-routes)，会议来源不自动归 vlog。

## T03 公司与产业故事

- 观看问题：公司为什么作出这个选择，什么利益或约束推动了它，谁的选择因此改变？
- 素材：具体公司动作、原有做法、决策代价、商业模式、供需关系、采用条件与竞争后果。
- 类型方法：读取 [公司与产业内容路线](type-methods.md#industry-routes)。可用原有利益冲突链、反常决策到需求闭环（C20）、新进入者到竞争规则变化（C21）、既有积累到新供给（C33）；C82 补充技术、效率与开放方式怎样连接采用选择。
- 内容推进：从一项需要解释的具体动作或反常变化出发，追踪相关主体为何行动，最后给出关系清楚的判断。产品、参数、人物与外部反应各承担不同证据任务。
- 结尾选择：可收束到公司位置、受影响的具体选择、尚未结束的竞争，或后续可观察的验证条件；不要求每篇宣告某一方彻底胜出。
- 常见失败：先宣布格局再找证据；人物性格代替商业解释；不同投入和价格直接拼成胜负；用热度与名人反应代替利益链。
- 边界：解释发布项目本身为主归 T11；解释公司为何决策及其行业后果为主归本类。人物命运为主归 T05。用户指定类型可保留并加辅助标签。

C98 补充发布前公司角色：事件窗口 → 旧身份与新任务 → 相关业务定位 → 共用能力与投入 → 使用者角色变化；愿景、已发生与预期分开，详见 [公司产业方法](type-methods.md#industry-routes)。

C144 补个人旧作与新场景的小对象入口，现归档且方法保留；有材料才把场景联结扩成生态供给解释，见 [公司产业方法](type-methods.md#industry-routes)。

C154 的成本与采用反馈进入常用，C144 转归档保留个人小对象入口；商业动作如何接回收益见 [产业关系](type-methods.md#industry-routes)。

## T04 科技与人的处境

- 观看问题：这项变化让谁得到什么、失去什么，或必须重新选择什么？
- 素材：人物处境、真实任务与关系、受益和代价、技术到后果之间的桥梁。
- 推进：具体处境或冲突 → 技术改变了哪个环节 → 不同角色如何受影响 → 选择或讨论空间。
- 可选方法：教育、就业、家庭、消费与人机关系；从核心人群的真实利益向更广共鸣扩散。
- 常见失败：凭空制造焦虑；把所有能力提升写成失业；一个个案直接代表整个系统。
- 边界：已经发生或直接可解释的人的处境是主线；多步未来链条是主线时归 T06。

C117 支持“项目依赖 → 服务变化 → 受影响任务 → 选择节点”的条件性入口，详见 [依赖与选择](type-methods.md#human-dependency)；这些条件性样本不验证全部处境类型，也不继承原稿情绪立场。

C126 补共同公共麻烦到互补方案，C129 补地方服务约束到人的机会；与 C117 一起见 [处境方法](type-methods.md#human-dependency)，不将个案或愿景等同普遍收益。

C178 补供给容量变化的进入窗口：区分已有与候选用户、变化状态和选择空间，见 [处境方法](type-methods.md#human-dependency)。

## T05 科技人物故事

- 观看问题：此人作出了什么不寻常的选择，它怎样改变故事走向？
- 素材：关键事件、真实互动、选择代价、转折与前后呼应；履历仅作支持。
- 推进：有性格的动作或反差 → 必要背景 → 关键选择／转折 → 结果与主题。
- 可选方法：人物短故事、传奇经历、共同主题群像；群像中每个人用不同事件证明共同主题。历史回环可提供尺度，不能压倒当前事件。
- 常见失败：成就清单；名人挂名；共同特征只在结尾宣布；借旧事虚构当事人动机。
- 边界：不因出现名人就归本类。结尾可以落在个人选择，不必推演产业未来。

## T06 趋势与未来推演

- 观看问题：眼下的多个变化合起来说明什么，后续最可能改变哪个环节？
- 素材：当前事实、相关独立信号、时间前史、因果桥梁、限制与反向证据。
- 推进：眼前变化 → 关联证明 → 变化机制 → 下一层后果 → 回扣主命题。
- 已认可方法：确认存在代际变化的重大模型、智能体或平台更新，默认读取并使用 [角色跃迁](type-methods.md#role-change) 的适用公式；此次整理不撤销原有用户认可。只有性能小幅提升时不强套。
- 其他方法：C29 的 [小闭环到规模条件](type-methods.md#trend-small-loop) 用具体服务连接复制变量与共同缺口；C53 补充部署约束与布局变化、当前测试到扩容计划的层级；C89 补充基准到应用后果的桥梁与取舍；围绕同一主题选择两三个后果；预言要说明归属和推理依据，不把人物预测变成已发生事实。
- 常见失败：热点拼盘；类比当证明；十个后果同等展开；把猜测说成完成状态。
- 边界：以当前科研机制为重点归 T02；以当下公司利益关系为重点归 T03。

C127 补充未来概念材料：从反常目标进入，以系统职责组织长材料，区分方案描述与结果层级，见 [推演与材料层级](type-methods.md#trend-small-loop)。

C140 补远目标到阶段依赖，技术路线与商业价值分开过桥，见 [条件与层级](type-methods.md#trend-small-loop)。

C183 补参与愿望与影视工作分工的桥梁，归档但方法保留；产物片段与整部作品分开解释，见 [任务与条件层级](type-methods.md#trend-small-loop)。

## T07 科技趣闻与文化现象

- 观看问题：这件科技圈趣事为何有趣，它透露了什么人性或文化？
- 素材：完整事件、真实反差、人物反应、科技或品牌文化背景。
- 推进：有趣事件 → 必要背景／反转 → 谈资或讨论入口。
- 可选方法：C30、C49、C55、C92、C113 的 [科技谈资与材料分层](type-methods.md#curiosity-material)；分别按异常材料、文化体验、竞赛动作选择，不拼成一条固定结构；模仿现象、公众形象、圈内习惯与文化反差；轻内容可以停在趣味，不必做宏大结论。
- 常见失败：离开科技背景变成泛八卦；为冲突臆测动机；没有事件只有嘲讽。

C113 补充科幻复刻与可调角色互动，进入常用；C92 的澄清承接转归档但方法保留，详见 [科技谈资方法](type-methods.md#curiosity-material)。

## T08 线下大会 vlog

已有 P01 正例、C16、C26、C32、C51、C134 共六篇常用爆款全文；C14、C15、C24、C47、C67、C70、C84、C90、C103、C114、C52 全文归档，方法保留；P01 的原对照分析保留。只学习内容组织；无数值数据不影响记录爆款身份，也不推断单一做法的因果效果。

- 观看问题：作者从现场带回什么发现，它为什么值得观众知道？现场观察可以导向公司判断、能力机会或人物发现，不强制按行程排列。
- 三条可选路线：观点统领的现场观察（C14 多组论据、C24 流程与体验解释、C32 制造回溯、C47 隐形服务、C51 同任务到体系、C52 移动任务合集、C84 主动体验合集）；能力与使用机会互证（C15 能力先行、P01 人物结果先行、C67 双模型分工、C70 推理与采用、C90 原型与创作条件）；行程推动发现（C16）。按材料选择，详细方法见 [现场 vlog 内容方法](type-methods.md#onsite-vlog)，不要求一条视频拼齐三条路线。
- 素材选择：现场反应、产品演示、商业资料、空间对照、人物行动与生活细节各有职能。让它们共同推进主命题；只有热闹和身份不能代替产品或观点证据。
- 创作重点：观众跟随的是一个逐步成立的发现；多项产品、论点或多个场地都能成为结构，前提是共同兑现观看承诺。编号列表不自动等于流水账，行程也不自动等于故事。
- 细节取舍：保留能提供独特观察、反差、关系或人物投入的现场细节；会后相处也可承担证据和情绪落点，不能一律删作琐事。纯粹重复热闹、路程或品牌名的片段才优先压缩。
- 常见失败：观众只看到行程与展品，不能复述作者发现；宏大观点与人物／产品脱节；以参会投入代替论证；跨行业扩展后失去共同观看收益。
- 材料不足：可先设计待拍内容和方向；缺失的经历标为待补，不能编造完成态现场或实测。仍默认干净口播，原语言、开头和交付规则保持独立。
- 边界：用户指定本类的现场观察稿可含发布会和产业判断标签，不因没有行程故事强行改类；仅看直播汇总发布信息归 T11。商业合作身份须由用户明确，不能根据赞美产品推定商单。

C103 补充现场发现转用途分组：动态吸引 → 人流与转场 → 生活用途 → 到场决策，归入既有行程发现与现场合集，详见 [vlog 方法](type-methods.md#onsite-vlog)。

C114 补充单展台的用途递进：文化结果 → 亲手试用 → 日常编辑 → 专业信息可用。按用途关系解释各层，不强造技术同源，合并到 [现场能力与机会互证](type-methods.md#onsite-vlog)。

C134 的情境回应与组件分工进入常用，C52 移动合集转归档，方法保留；现场观察、员工讲解与展示材料分别解释，合并至 [能力与机会互证](type-methods.md#onsite-vlog)。

## T10 产品商单

用户已明确将产品商单纳入范围，不沿用旧版禁止商业推广的规则。C11 只提供结构摘要，以下框架仍待完整商单案例训练。

- 观看问题：这个合作产品具体替哪类人解决什么麻烦，证据是什么？
- 素材：合作方与产品、目标人群、核心需求、已确认卖点、可用演示／体验、必含信息与限制、合作目标和已确认的行动入口。
- 推进候选：真实需求／故事入口 → 产品自然进入任务 → 能力与结果证明 → 适用范围 → 与合作目标一致的行动。不得先制造产品无法解决的痛点。
- 内容重点：把品牌要求翻译为观众能理解的收益；卖点有主次，必含信息不能自动变成等长段落；合作不等于必须促销，也不默认添加优惠或购买入口。
- 常见失败：开头有故事，产品一出现就切换为卖点朗读；所有能力都称最好；虚构客户、订单、收益或亲测体验；用普通资讯或独立测评身份掩盖合作性质。
- 材料不足：先完成可支持的内容方向，把缺失的关键 brief 集中列出；未确认的价格、权益、效果、入口不写成既成事实。遵循事实边界与发布红线，真实呈现合作关系，不提供规避商业标识的写法。
- 边界：以履行合作目标为主才归本类；普通产品报道不自动成为商单。合作对象身份以用户信息为准，不自行把某品牌认定为合作方。

## T11 发布会

- 观看问题：这场发布最值得关注的变化是什么，为什么值得现在知道？
- 素材：发布记录、关键演示、新旧差异、各产品间关系与核心共鸣人群。
- 结构选择：先读 [发布会结构选择](type-methods.md#launch-routes)。单品足以代表总命题时使用主角金字塔；总命题依赖多项产品关系时，选体系递进、商业逻辑串联或基础设施拼图。单产品发布围绕其核心变化展开。
- 可选组织：同一总命题的能力递进、公司路线变化、最强产品深讲；有编号和多项目并不等于流水账，每项承担不同解释任务才有共同观看收益。详细证据见 P04、C17、C03、C45、C61、C75；C61 补充单模型的能力、可靠性与采用条件，C75 补充买卖两端的工作关系；不把样本推广成所有发布会的公式。
- 常见失败：官方顺序即稿件顺序；多个产品反复重建受众；用亮点数量代替观看承诺；把观看直播写成亲临现场。
- 边界：发布内容本身是主线归本类，到场经历是主线归 T08；从发布出发证明更长远的趋势可归 T06。

C130 用实时交互关系与多端任务解释单模型发布，进入常用；C61 转归档保留能力采用方法。见 [发布会路线](type-methods.md#launch-routes)。

C181 补代表工具构建到模型和生态条件，官方示范、用户创作与他人扩散分别看，见 [发布会路线](type-methods.md#launch-routes)。
