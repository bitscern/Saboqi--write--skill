# 内容案例索引

按 [内容类型](content-types.md) 查案例；详细分析统一见 [case-notes.md](case-notes.md)。每个案例只存一份分析，可附跨类型标签；常用容量与轮换以 [案例容量表](case-gaps.md) 为准，超额稿照常学习并归档；成对／成组三篇的关系与原始编号全部保留。

## 原稿、分析、方法分层

- **原稿**：保存用户提供的完整文案，未来放在 `cases/<案例编号>/source.md`；多稿对照分别保存 `source-a.md`、`source-b.md` 等。保留顺序、完整开头与结尾；元数据和分析放在正文外。首次有原稿时再创建文件，不建空壳，不从摘要补写。
- **分析**：在 `case-notes.md` 记录观看承诺、信息取舍、推进链、结论、素材依赖和适用条件，不复制全文。原文保留不等于学习语言，默认仍只分析内容。
- **方法**：类型方法进入 `content-types.md` 或 `type-methods.md`；跨类型成立的原则进入 `topic-core.md` 或 `editorial-system.md`。索引和分析记录只链接，不再维护一套重复的“稳定结论”。

首次学习有全文时读取全文；只有片段就只判断局部，不推断整稿结构。正常写稿先读取对应类型方法，有需要再查一至两条“常用”案例分析；“归档”只在追溯或明确需要时读取；只有核对具体推进、篇幅或原文证据时才读取对应全文。不要求每次加载所有案例。
